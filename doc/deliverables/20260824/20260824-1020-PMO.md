# 项目现状评估报告

## 结论区

项目当前处于“可运行的 MVP 联调原型”阶段，尚未达到“稳定可验收的产品闭环”。核心链路已经从早期模块骨架推进到：

`文本输入 -> 规则提取 -> 三类数据采集 -> 候选池适配 -> ranking -> 前端展示`

当前最值得继续投入的是稳定和收口，而不是立即扩展实时语音、复杂路线优化或机器学习推荐。

| 模块 | 当前判断 | 证据/说明 |
| --- | --- | --- |
| FastAPI 后端 | 可启动 | `/`、`/health`、`/openapi.json` 实测返回 200 |
| 文本关键词提取 | 已实现 | 正则/词典提取目的地、日期、预算、人数和偏好，并生成 `algorithm_input` |
| ASR | 已接入首版 | FunASR 音频转文字接口存在；本轮未执行真实音频转写 |

## 主要风险

1. **文档与代码不一致。** `doc/流程图版开发进度.md` 仍写 ranking、前端和 Top N 未开始；README 的 Ranking Scaffold 说明也仍写“未接入 pipeline”；`backend/app/main.py` 根接口仍返回 ranking/frontend 为 planned。
2. **外部服务导致 E2E 不可复现。** pipeline 每次请求串行执行三个采集脚本，受 API、网络、限流和第三方服务超时影响，单次请求可能很慢或直接失败。
3. **存在明文 API Key。** place 和 food 脚本中有高德 key，应该立即轮换并迁移到环境变量。
4. **酒店 fallback 不覆盖网络异常。** fallback 逻辑只在成功返回但没有候选时触发；Overpass 抛出异常时，脚本直接结束且不产出结果。
5. **当前 ranking 不是路线规划。** 它按景点、餐饮、酒店分别排序；前端再按固定索引组合三条路线，尚未做空间聚类、时间约束、行程顺序或组合级评分。
6. **测试体系不足。** 没有稳定的 pytest/CI smoke test；当前联调脚本会写本地产物且依赖外网，不能作为唯一验收依据。
7. **ASR 成本和资源风险。** FunASR/Torch 及模型首次加载可能下载模型并消耗较多 CPU/内存，本轮未验证真实音频链路。
