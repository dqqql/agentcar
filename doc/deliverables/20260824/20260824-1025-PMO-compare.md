# intelligent-cockpit-travel 对比评估

## 结论

`D:\Dql\Desktop\intelligent-cockpit-travel` 与当前 `agentcar` 的 Git 提交基线相同，均为 `0def779`。对比目录没有新的提交，主要推进都存在于未提交工作区，因此应视为“实验性工作区进展”，不是已发布版本。

## 相对当前项目的实质推进

### 1. ranking 算法扩展

对比目录将 `backend/app/services/ranking/service.py` 从当前的规则排序服务改成了 `POIRecommendationService`，增加了四个阶段的代码结构：

- 阶段 1：评分、距离、热度归一化和客观得分。
- 阶段 2：基于 `TfidfVectorizer` 和标签的主观偏好相似度。
- 阶段 3：基于历史 POI 和标签重叠的序列偏好模拟。
- 阶段 4：客观、主观、序列分数融合，并截取 Top-K。

同时新增依赖：`numpy`、`scikit-learn`，并将 ranking 服务类名改为 `POIRecommendationService`。

判断：这是算法结构上的推进，但阶段 3 实际是规则模拟，不是训练好的 Bi-LSTM；阶段 4 也没有真实损失函数或训练流程。因此可以称为“多阶段推荐算法原型”，不能称为已完成的深度学习推荐模型。

### 2. 酒店数据源迁移

对比目录将酒店数据脚本从 Nominatim + Overpass 改为高德地理编码和高德周边搜索，并增加了：

- 高德酒店分类和分页搜索。
- 高德返回字段到酒店标准字段的转换。
- 高德请求异常时回退到模拟酒店数据。
- pipeline 中城市映射改为中文城市名，更适配高德地理编码。

判断：这直接针对当前项目实测到的 Overpass 504 问题，方向上能降低对 Overpass 的依赖；但它新增了高德 API key 和外部服务依赖，仍需验证配额、错误处理和数据质量。

### 3. 依赖和文档实验材料

- `requirements.txt` 增加了 `numpy`、`scikit-learn`。
- `doc/poi_recommendation.py` 及 `doc/app/` 下存在更完整的算法实验代码和重复的服务文件，但这些内容位于被 `.gitignore` 忽略的 doc 范围，未作为正式运行模块纳入版本控制。
